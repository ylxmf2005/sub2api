# 结算池每周期加入规则

## Problem Frame

现有结算池需求见 `docs/brainstorms/2026-04-25-settlement-pool-billing-requirements.md`。原需求把参与者名单视为管理员维护的池成员名单，并隐含跨周期保留参与身份。新的产品目标是把“长期准入资格”和“当前周期占位承诺”拆开：管理员控制谁有资格进入池子，用户每个周期主动决定是否承担占位费。

这个补充需求专门定义每周期加入、管理员代加入、移出当前周期和未加入候选用户可见性的规则。

## Requirements

**长期候选资格**
- R1. 管理员可以维护每个结算池的长期候选名单；只有候选用户可以在用户侧看到该结算池并自行加入当前周期。
- R2. 管理员把用户加入候选名单时，默认只授予长期准入资格，不自动加入当前周期。
- R3. 管理员可以在后台执行复合动作：把用户加入候选名单，并同时加入当前周期。用户侧不展示“联系管理员加入”之类提示。

**每周期加入**
- R4. 每个新周期开始时，保留长期候选名单，但清空当前周期参与者；候选用户需要重新点击加入当前周期。
- R5. 用户加入当前周期后，即视为承担该周期完整占位费；无论加入发生在周期开始、中间还是接近结束，都不按时间比例折算固定占位费。
- R6. 用户加入当前周期后，不能自行退出当前周期。之前的“未使用可自行退出”产品逻辑应删除，不再提供用户侧退出入口。
- R7. 候选用户未加入当前周期时，绑定该结算池的 API Key 请求不得自动加入，也不得放行使用；用户必须先在页面明确点击加入当前周期。
- R8. 候选资格本身不计入当前周期结算；未加入当前周期的候选用户不参与固定占位费分摊、动态费用分摊或参与者人数统计。

**可见性**
- R9. 候选用户即使尚未加入当前周期，也可以在结算池页面看到池子名称、当前周期参数、参与者明细、实时预估明细和自己的历史周期。
- R10. 非候选用户不应在用户侧看到该结算池，也不能自行加入当前周期。

**管理员当前周期修正**
- R11. 管理员可以在后台把候选用户强制加入当前周期。
- R12. 管理员可以无条件把用户从当前周期参与者中移除，即使该用户本周期已经产生用量。
- R13. 管理员移出当前周期只影响当前周期参与身份，不移除长期候选资格。
- R14. 管理员移出当前周期后，只要候选资格仍在，用户可以在同一周期再次自行加入。
- R15. 管理员移出当前周期后，如果用户没有在该周期重新加入，则锁定结算时该用户不出现在该周期结算明细中，已发生用量也不展示在该周期结算明细中。
- R16. 管理员移出当前周期后，如果用户在同一周期重新加入，则恢复为当前周期参与者，并按整个周期统计该用户在该池的全部用量。

## Success Criteria

- 新周期开始后，候选用户不会自动承担占位费，必须主动加入当前周期或由管理员后台加入。
- 加入当前周期是清晰的占位承诺：加入后不能由用户自行退出，并承担完整固定占位费。
- 候选但未加入当前周期的用户可以查看授权范围内的明细，但不参与当前周期费用分摊。
- API 请求不会绕过用户确认；未加入当前周期的候选用户请求会被拒绝。
- 管理员仍能处理私下运营场景：发候选资格、代用户加入当前周期、从当前周期移除用户。
- 用户侧页面保持简洁，不展示“找管理员加/删”等私下流程提示。

## Scope Boundaries

- 不改变结算池的阶梯算法、市场封顶价、固定池/动态池计算规则。
- 不新增在线支付、收款凭证、发票或资金流处理。
- 不要求用户侧解释管理员后台代加入、移出当前周期等私下运营能力。
- 不改变已锁定历史周期快照。
- 不开放非候选用户查看或加入结算池。

## Key Decisions

- 长期准入和周期参与拆分：候选名单解决“谁有资格”，当前周期参与解决“谁承担本周期占位费”。
- 新周期不自动继承参与者：避免用户在没有明确确认的情况下继续承担新周期占位费。
- 用户加入后不能自行退出：加入就是本周期承诺，减少规则分支和争议。
- 管理员保留后台修正权力：线下运营需要兜底，但这些能力不在用户侧提示。
- 候选未加入也能看当前明细：候选用户已经被授权进入池子，透明度优先于隐藏当前明细。
- 重新加入后统计整个周期用量：该规则贴近现有按周期窗口结算的产品心智，避免引入复杂的分段参与解释。

## Dependencies / Assumptions

- 主需求文档中的结算池周期、锁定快照和费用展示语义继续成立。
- 管理员对候选名单和当前周期参与者的后台操作被视为可信运营动作。
- “已发生用量不展示”仅指从当前周期结算明细中排除被移出且未重新加入的用户，不改变底层审计或系统日志的保留策略。

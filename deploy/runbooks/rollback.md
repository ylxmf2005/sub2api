# Rollback Runbook

## 触发条件

出现任意一种情况，直接进入回滚判断：

- `/health` 不通过
- 管理员无法登录
- 关键数据缺失
- 代表性 API 请求失败
- 新栈启动后发现密钥或 2FA 连续异常

## 回滚原则

- 先恢复可用性，再谈根因
- 不在故障现场临时发明迁移逻辑
- 使用切服前最后一次确认过的备份

## 回滚步骤

1. 停止新栈
2. 保留故障现场日志
3. 恢复旧部署目录、卷或二进制安装结构
4. 恢复旧数据库 / Redis / 运行时数据
5. 启动旧栈
6. 做最小烟测确认旧环境恢复

## 回滚后必须记录

- 失败版本
- 失败时间
- 触发回滚的具体现象
- 哪一步通过、哪一步失败
- 是否与数据、密钥、compose 配置、镜像版本有关

# Cutover Runbook

## 目标

把旧部署切换到新的私有 fork + 本地构建 + Compose 运行模式，同时保住现有数据。

## 0. 切换前冻结条件

- 最新 release bundle 已在本地生成
- 已跑完服务器审计
- 已完成最终备份
- 已确认关键密钥是否沿用
- 已准备回滚包

## 1. 最终确认

- 旧环境停止前，不再对管理后台做结构性修改
- 记录旧部署的当前版本、目录、服务名、卷名
- 明确本次目标部署目录

## 2. 停写与备份

- 停掉旧部署的写入入口
- 立刻执行最终备份
- 记录备份目录与时间戳

## 3. 准备新目录

- 放入：
  - `docker-compose.local.yml`
  - `docker-compose.private.yml`
  - `.env`
  - `data/`
  - `postgres_data/`
  - `redis_data/`
- 导入或复制旧数据
- 确认关键密钥已经进入 `.env`

## 4. 第一次启动门槛

在下面几件事都完成之前，不允许第一次 `docker compose up`：

- 旧数据已复制或恢复
- `.env` 已校对
- 私有镜像已 `docker load`
- Compose 配置已通过预检

## 5. 启动新栈

- 使用双文件 Compose 启动
- 观察容器健康状态
- 如果使用 `datamanagementd`，同步确认 socket 挂载

## 6. 烟测

至少验证：

- `/health` 可用
- 管理员可登录
- 用户和 API Key 数量与迁移前大体一致
- 账号池与代表性请求可工作
- 数据目录和数据库行数检查通过

## 7. 宣布切换完成前

- 记录新部署目录
- 记录 release tag
- 记录最后一次可用回滚包
- 再决定是否下线旧部署
